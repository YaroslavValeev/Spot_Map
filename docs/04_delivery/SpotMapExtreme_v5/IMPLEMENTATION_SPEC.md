## 1. Погода — целевой дизайн
**Верхняя часть страницы:** заметные числовые `°C воздух`, `°C вода`, `ветер м/с + направление`, актуальность и ссылка на источник. Контекст верхнего блока — выбранный спот; без выбора — выбранный регион с текстом «Погода региона». Не показывать не относящуюся к акватории температуру воды.

**Карта:** кнопка «Ветер — вкл/выкл», прозрачный слой ветра поверх действующей Яндекс Карты; сама карта, геометрия, пользовательские маркеры, зум и кластеризация не меняются. Слой рисуется ниже маркеров, сохраняет кликабельность. Пояснение легенды м/с, прогнозная дата/час. Опциональная лента `сейчас | +3 ч | завтра`, привязанная к часовому поясу спота. При недоступном слое интерфейс честно показывает `Ветровой слой недоступен`.

**В карточке:** воздух, вода, направление, средний ветер, порывы, почасовой прогноз; «Оценка катания» выдаётся ТОЛЬКО после утверждения вручную ветрового профиля спота и дисциплины. При отсутствии профиля: `Не оценено`.

### Провайдеры
1. Yandex Weather API — предпочтительный источник визуальных `windSpeed` тайлов для Яндекс Карты. Документация: https://yandex.ru/dev/weather/doc/ru/concepts/tiles . Требует проверенного коммерческого права на погодные тайлы, API ключа, уточнения цен и условий публичной публикации/кэширования. В документации есть проекции EPSG:3395 и EPSG:3857 и таймлайн. Направление и порывы получать из точечного API (не ожидать их в тайле скорости). Технический способ авторизации тайлов согласовать с Яндексом; не раскрывать серверный ключ в браузере.
2. Open-Meteo (пилотный REST-провайдер для точечного прогноза): https://open-meteo.com/en/docs . Hourly/current: `temperature_2m`, `wind_speed_10m`, `wind_direction_10m`, `wind_gusts_10m`, `precipitation`; `wind_speed_unit=ms&timezone=auto`. Пример URL для теста, НЕ для коммерческого продакшена:
`https://api.open-meteo.com/v1/forecast?latitude=56.1344&longitude=37.546165&current=temperature_2m,wind_speed_10m,wind_direction_10m,wind_gusts_10m&hourly=temperature_2m,wind_speed_10m,wind_direction_10m,wind_gusts_10m,precipitation&forecast_days=3&wind_speed_unit=ms&timezone=auto`
   Коммерческий API — `customer-api.open-meteo.com`, отдельная лицензия: https://open-meteo.com/en/pricing . Не считать бесплатную версию разрешённой для коммерческого использования.
3. Если тайлы Яндекса по цене/лицензии недоступны, проверить лицензированную ветровую подложку OpenWeather `wind_new` https://openweathermap.org/api/weathermaps и корректность проекции с существующей Яндекс Картой. Важно: Яндекс Карта сохраняется; погодный провайдер не обязан быть картографическим провайдером.

### Температура воды — отдельный тип данных
Не брать температуру воздуха как суррогат. Yandex Weather `waterTemperature` доступен не повсеместно, прежде всего для побережий. Open-Meteo Marine не является источником температуры внутренних водохранилищ. Приоритет: (a) измерение на месте датчиком/представителем клуба, с глубиной и точкой замера; (b) лицензированные спутниковые данные **только** при наличии покрытия и достаточной актуальности, например Copernicus CLMS LSWT; (c) `Нет свежего измерения`. Хранить `measured_at`, `source`, `location`, `depth_m`, `measurement_method`, `confidence`, `expires_at`.

### Weather Provider интерфейс
`forecast_point(lat,lon,times)` -> нормализованная структура `{observed_or_forecast_at, provider, updated_at, air_c, wind_mps, direction_from_deg, gust_mps, precipitation_mm}`. По умолчанию единицы `°C`, `м/с`, `° от Севера, ОТКУДА дует`. UTC timestamps + местный TZ спота для UI. Серверный адаптер, кэш 15–30 минут (фактическую TTL согласовать с лицензией), last-good-data с меткой устаревания, backoff/circuit breaker, квоты. Повторные загрузки карты не должны создавать новые API-запросы на каждый маркер.

## 2. Ручной ветровой профиль — уникальное ядро SpotMap
`WindProfile(spot_id, ride_area_id?, discipline_id, approved, version, sectors[], author_id, reviewed_at)`.
Каждый сектор определяется **направлением, ОТКУДА дует ветер** (`0°=С`, `90°=В`, `180°=Ю`, `270°=З`), может пересекать 0°. Указывать вручную: `from_deg`, `to_deg`, `verdict(excellent/good/limited/unsuitable)`, дополнительные лимиты `max_wind_mps`, `max_gust_mps`, текст о рельефе и разгонах волны. Интервалы должны не перекрываться для выбранного спота/дисциплины. Незаполненные секторы не получают прогнозную оценку. Профиль сначала создаётся в черновике, публикуется после утверждения Ярославом.

Модуль `spotmap_wind.py` реализует строго **только** ручную оценку направления, скорости и порывов. Никаких стартовых порогов или придуманных SpotScore. Выход — `estimated` с вердиктом, либо `not_configured`, `no_rule_for_direction`, `ambiguous_profile`, `missing_forecast` и т.п. Качество прогноза не равно безопасности занятия.

Расширение: оценка с учётом времени после изменения ветра, состояния воды, береговой защиты, длины разгона, судоходства, течения, квалификации райдера, вида катания и конкретной установки. Добавлять после сбора реальных измерений и ваших экспертных правил.

## 3. Переходы на запись и аналитика
На карточке **одна** главная CTA `Записаться у клуба`, ведущая на проверенную ссылку клуба. Внутренняя запись и оплата сейчас не создаются. Диспетчеризация через серверный `GET /go/{verified_booking_link_id}` -> регистрация `outbound_booking_click` -> 302 redirect по разрешённой URL. Клиенту сообщать «Вы переходите на сайт клуба», но не «Вы записаны». Удалять невалидные ссылки, не допускать произвольный URL в redirect query (open redirect), проверять HTTPS, конечный домен, дату проверки и допустимые параметры UTM. 

События: `spot_view`, `club_view`, `booking_cta_view`, `booking_cta_click`, `outbound_booking_click`, `confirmed_booking` (ТОЛЬКО из подтверждения партнёра, валидированного промокода/атрибутированной отчётности или webhook), `review_submitted`. Конверсии делить на `CTR переходов` и `подтверждённые записи`. Никаких «реальных записей» из одних кликов. Показатели в админке: views -> clicks -> confirmed, по клубам, дисциплинам, источнику трафика, UTM и неделе; уникальные события, защита от ботов, consent/privacy.

## 4. Спортивный паспорт
- Spot: название, coords акватории/границы, ручная точка старта, подъезд, безопасный/полевой въезд, водоём, судоходство, длина рабочего участка, ширина, минимальная глубина (источник/сезон), волна, ветер, ограничения, сезон, источники.
- RideArea: отдельная акватория/створ с осью движения, помехами, разгонной дистанцией, береговыми ориентирами, ручным ветровым профилем.
- Club: проверенные контакты, работа, график, оператор, ссылка на запись, цены, возраст/уровни, инструкторы, источник/время проверки.
- Installation: ring/reverse, бренд/модель, фактическое наличие, длина, трасса, оборудование, состояние, принадлежность клубу, фотографии.
- Boat: производитель/модель, год если подтверждён, комплектация, доступность по услугам.
- Infrastructure: пирс, слип, парковка, санузлы, раздевалки, прокат, питание, спасение, медпункт, доступность, точка входа.
- Media: права, автор, описание, дата, видеообзор, связь с объектом.
Поле может иметь статус `confirmed`, `source_claim`, `unverified`, `stale`, `disputed`, `not_applicable` с собственной отметкой времени.

## 5. Обновление 1 раз в неделю
Scheduler запускает `weekly_source_check` один раз в 7 дней (с временем фиксированного TZ). Раздельные адаптеры только для разрешённых источников: официальный сайт, RSS/публичный API, согласованные страницы клубов и агрегаторы с допустимой лицензией. Проверять robots/ToS, таймауты, rate limit, ETag/Last-Modified, retries, дедуп. Фото и полные отзывы нельзя автоматически копировать без прав.

Парсинг -> raw snapshot с `source_uri`, `fetched_at`, `checksum` -> извлечение полей -> сравнение с предыдущим снимком -> `ChangeProposal` -> автоматическое обновление только безопасных подтверждённых изменений -> конфликт на модерацию. Недоступность сайта не означает закрытие клуба. Не перезаписывать вручную проверенные сведения источниками более низкого доверия. Поле `last_source_checked_at` отдельно от `last_verified_at`.

## 6. Рейтинги: дистанционная оценка и личная полевая экспертиза
Три независимых представления, НЕ смешивать до утверждения методики:
1. `ExternalRating`: Яндекс/2ГИС/другие; исходный балл, число оценок, дата наблюдения, ссылка на оригинал, лицензия/права на показ. Встраивать официальный виджет, где он разрешён, или ссылку; не копировать массово защищённые отзывы. Рейтинг **клуба**, не физической акватории.
2. `RemoteAudit`: авторская **предварительная дистанционная оценка SpotMap**, явно `НЕ ПРОВЕРЕНО НА МЕСТЕ`. Индикаторы доказательств: фото/видео, спутниковые/географические ограничения, оборудование, подтверждённые контакты, инфраструктура, данные об акватории и защищённости; 0–5 только по тем показателям, где есть доказательство; `unknown` для остальных. Весы и формулу общего рейтинга пока **не утверждать**. Сохранять список проверенных пунктов и coverage ratio.
3. `FieldExpertAudit`: личный визит Ярослава, дата, дисциплина, погодные условия, раздельные оценки, фотографии, ссылка на видео, версия методологии. Статус `ПРОВЕРЕНО ЛИЧНО`. После визита выполнить повторный расчёт только по утверждённым весам и сохранив все исходные срезы. Никогда не объявлять предыдущие дистанционные показатели личной проверкой.

Отзывы пользователей: аутентификация, модерация, защита от накруток, даты, отдельные оценки Spot и Club, отметка `посещение подтверждено` только при доказательстве. Сами по себе публичные отзывы третьих лиц — источник внешней репутации, не внутренняя подтверждённая экспертиза.

Возможные внешние данные: официальный Яндекс виджет отзывов при разрешении, 2GIS Places API (`items.reviews`, общая статистика и рейтинги при действующих условиях лицензии), сайты клубов, собственные документы, разрешённые фото и видео. API Яндекс Поиска по организациям запрещает сохранять/изменять возвращённые данные по стандартной лицензии — не строить архив копий без дополнительного права. Источники приведены в README.

## 7. Личный кабинет пользователя
Лёгкая авторизация через выбранного провайдера после аудита существующей системы (например, Telegram/email); встроенная панель, избранные Spot/Club, история посещений пользователя, собственные отзывы, подтверждение/неподтверждение посещения; история записи у внешнего оператора остаётся `неизвестна`, если нет связанного события. Согласия на обработку персональных данных, права на удаление и защита доступа. Не создавать фиктивные тренировки.

## 8. Модульная админка клуба — без отдельной страницы
Кнопка в карточке `Управлять клубом` отображается только подтверждённым операторам. При отсутствии доступа — `Запросить управление` с контактами модератора: Telegram @MyWave23, e-mail y.valeev@gmail.com. Панель drawer/modal со вкладками: `Информация | Цены/Услуги | Фото/Видео | Расписание | Как добраться | Статистика | История изменений`.

Заявка на роль `ClubOwner/ClubEditor` проходит проверку модератором. Backend RBAC, ownership каждого клубного объекта, audit log, версии, загрузки только разрешённых типов, проверка размеров/вредоносного контента, откат. Опубликованные изменения проходят очередь модерации, кроме явно разрешённых. Маршрут с точками `парковка/ворота/пирс/старт` в виде упорядоченного списка геометок и инструкции по подъезду.

## 10. Критерии завершения
- Яндекс Карта не заменена; действующие маркеры/кластеризация/навигация не ухудшены.
- Верхняя температура для выбранного спота, вода не выдумана, источник и свежесть указаны; нет воды -> `Нет измерений`.
- Ветровой слой включается/выключается и реально рисует авторизованные тайлы в production, либо корректно уведомляет об отсутствии доступа; нет ложного «сейчас» от прогноза другого часа.
- В карточке с неутверждённым профилем `Не оценено`; ручные параметры версионированы, перекрытия секторов блокируются.
- Outbound click учитывается, confirmed booking НЕ возникает из клика.
- Точность паспорта и рейтингов подтверждена происхождением данных.
- Разрешённый кабинет клуба работает без отдельной страницы, ограничения прав проверены на backend.
- Есть модульные, интеграционные, визуальные и мобильные тесты; ключи провайдеров не отдаются в HTML.
