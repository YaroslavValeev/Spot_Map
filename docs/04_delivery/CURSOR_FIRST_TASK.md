# Готовый стартовый промпт для Cursor Agent

Ты — технический руководитель и senior full-stack architect проекта SpotMap. Твоя задача — начать Sprint 01: Foundation & First Map. В проекте утверждён P0 для **вейксёрфинга и вейкборда — электротяги** (отдельные установки на одной площадке — самостоятельные объекты).

Сначала **прочитай** `AGENTS.md`, `README.md`, `docs/00_product/DECISIONS.md`, `docs/00_product/SpotMap_Product_Blueprint_v1.1.md`, `docs/01_architecture/SpotMap_Data_Model_v1.md`, оба паспорта в `docs/02_passports/`, `docs/04_delivery/SpotMap_P0_Implementation_Backlog.md`, `docs/05_quality/SpotMap_QA_Report.md` и существующую SQL-схему/JSON-контракты.

1. Проведи **аудит фактического репозитория** (директории, git status, тесты, конфликты контрактов). Ничего не выдавай за реализованное, если это лишь спецификация.
2. Подготовь короткий архитектурный план: выбранный стек (предложение обоснованное), модульные границы, ER/relationship карта, migration plan, карта/API, test plan и риски.
3. Прими в расчёт существующую infrastructure MyWave, но не трогай её без явного разрешения. Не хардкодь секреты.
4. Реализуй **первый небольшой технический вертикальный срез** в рабочей ветке: воспроизводимое окружение для тестового PostGIS, безопасный staging-импорт кандидатов (без автоматической публикации), базовый read-only geo API или первый минимальный API тест по ситуации.
5. Проверь и опиши Definition of Done. Каждый факт о реально существующих геопозициях должен иметь источник и статус проверки.
6. При выявлении расхождения между документами и схемой заведи ADR / задачу; не меняй канон молча.
7. В конце дай отчёт: что проверено, какие файлы изменены, результаты тестов, недоработки, точный следующий шаг.

**Категорические запреты:** не создавать фальшивые споты, координаты или отзывы; не публиковать частные raw данные; не применять draft SQL на production; не внедрять booking, оплату, соцсеть в Sprint 01; не утверждать полный каталог всех установок России, пока геопоиск не проведён.
